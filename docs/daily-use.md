# 日常使用与上线前配置

运行 `make`，打开 http://localhost:5173。管理员密码读取项目 `deploy/.env` 的 `ADMIN_PASSWORD`。账号密钥保存在加密凭证库，不填写到任务参数或人格提示词中。

## 1. 让机器人回复 QQ

1. 打开「系统与凭证」，检查数据库、Temporal、SDK 服务状态。
2. 在「模型接入」设置真实模型。现有 CodeBuddy iOA 配置使用 `glm-5.3`；新建会话时明确选择它，不选择名称带验收标记的测试配置。
3. 打开页面中的 NapCat 登录入口，扫码登录作为秘书的 QQ 账号。页面 token 与 QQ 登录是两件事；页面 token 在 `deploy/.env` 的 `NAPCAT_WEBUI_TOKEN`。
4. 在个人 QQ 设置中刷新连接，填入登录账号以及允许联系人的另一个 QQ 号，选择人格和模型，打开接收开关并保存。
5. 从允许的联系人账号发送「你好，记住我的称呼是……」，再问称呼，确认真实接收、回复与上下文。Web 中应出现对应 QQ 会话、运行和投递记录。
6. 在同一会话要求「两分钟后提醒我检查邮箱」，从定时任务页核对时间、接收会话和实际收到的提醒。

OneBot 支持私聊文本和允许群内的 @ 文本消息；官方 QQ 入口仍为私聊。QQ 收发框架可以替换，联系人、群授权和业务上下文由秘书服务控制。连接状态“在线”只说明接入状态，不能替代一次真实双向消息验证。

### 群聊使用

1. 在「人格」创建供群使用的人格，取消「使用所有已授权工具」，只勾选适合群成员使用且结果可公开的工具；也可以保持空清单，仅聊天。使用全部工具的人格不会出现在群人格选项中。
2. 将秘书 QQ 加入需要使用的群。在「系统与凭证 → 个人 QQ · OneBot 通道」填写「允许使用的 QQ 群号」（例如 `1128987429`），选择模型配置和「新群聊会话的人格」，启用并保存。每类允许列表最多 20 项；仅使用群聊时，可把私聊联系人列表留空。
3. 在 QQ 群中通过成员选择功能 **@ 机器人** 后发送文本。允许群内的所有成员都能这样使用，不需逐一添加到私聊联系人列表。未 @ 机器人的消息不会触发。
4. 到 Web 查看带群号和发言人标记的会话。同一个群的不同发言人、同一个人的不同群分别保存上下文，不复用私聊历史。
5. 在该群会话要求创建提醒，核对任务的来源会话。回复与提醒会发回原群并 @ 发言人，群成员均可看到；它们不会自动转成私聊通知。

群人格和私聊人格使用独立配置字段。邮箱正文、私人附件等工具结果可能出现在群回复中，给群人格配置工具时应按实际公开范围选择。移除允许群或停用接收后，该群不能再触发新执行或收到新发送。

## 2. 邮箱新邮件提醒

1. 在邮箱厂商的设置里启用 IMAP 并取得授权码/应用密码。
2. 打开「邮箱监听」，填写 IMAP 服务器、TLS 端口（通常 993）、完整邮箱账号、授权码，保存并启用。
3. 点击「测试邮箱连接」。它会真实登录并读取文件夹状态，不修改已读标记；填写错误时会显示失败原因。
4. 添加监听：默认 `INBOX`、每 5 分钟检查，选择之前已建立的 QQ 会话。选择群会话会将邮件提醒发到该群，个人邮件应选择私聊或 Web 会话；Web 会话仅在管理端查看通知。
5. 默认首次只记住当前邮件位置，避免把旧邮件全部提醒一遍。需要历史邮件时显式勾选首次提醒已有邮件。每次最多处理 20 封，积压分批处理。
6. 发送一封真正的新邮件后，核对最近检查结果、保存的邮件产物、任务通知和 QQ 投递记录。无新邮件时没有提醒；轮询本身不调用模型。

同一会话、同一文件夹通过此页面重复创建会更新同一个监听任务，不会新增重复订阅。修改频率保留游标。停用邮箱插件会暂停依赖任务；启用后显式恢复所需任务。插件配置/版本在任务启动时固定为快照，已经执行中的任务不会被配置更新中途替换。

邮件读取不会自动标为已读；授权 `mail.write` 后，秘书才能执行显式的标记已读工具。摘要模型是可选 API 配置，只有生成摘要时消耗模型额度。也可在 QQ 会话让 SDK 通过邮箱搜索工具读取邮件后自行概括。

## 3. 通知失败与恢复

- `sent`：消息服务确认已发送。
- `saved`：保存在 Web 的通知。
- `failed`：确定失败，可在「运行记录 → 任务通知」点击重试投递。只重发保存的通知，不重新运行模型、邮箱读取或视频解析。
- `uncertain`：外部结果不明，先核对接收方；界面不提供盲目重发。
- `pending`：已保存但投递尚未结束。服务重启和后台对账会继续处理；若平台操作曾开始却没有明确结果，会转为 `uncertain`，不会盲目重发。
- 模型失败、超时也会向 QQ 返回明确失败提示，详细错误保留在运行记录。
- 周期任务持续失败时，每小时最多提醒一次；每次失败仍写入执行记录。一次检查恢复成功后，之后的新故障可以再次提醒。

Temporal 在重启后继续调度和持久化等待，完成步骤不会仅因回放而重复执行。模型 SDK 的整轮内部不可任意恢复；副作用结果不明时不自动重跑整轮。

## 4. 视频与其它扩展

配置视频插件前先添加两个 API 配置：支持音频转写的 OpenAI 兼容服务、支持图片输入的视觉模型。CodeBuddy 文本 SDK 配置本身不等于这两种能力。

在「文件与解析」上传视频，点击「解析视频」创建后台任务，再从定时任务页立即执行。默认 100 MB、30 分钟；音频分段处理，抽帧最多 20 张并覆盖整个视频。处理失败会保留明确标注“未完成”的产物。抽样画面不能代表每一秒均经过视觉分析，只有音频文本时不伪造逐字时间戳。

人格可创建、编辑、复制、导入导出，并绑定会话；修改从下一轮生效。新增业务工具仍以独立插件包提供，无需改动模型 SDK 或消息通道。参见 [插件开发](plugins.md)、[SDK 使用边界](SDK_LIMITS.md)。

## 5. 当前真实联调前置条件

代码测试、浏览器测试和本地协议服务不能替代真实账号联调。完成以下项目才可确认对应能力可投入个人使用：

- QQ 当前登录在线、联系人或群已绑定，一次真实收件和回复、一次定时主动提醒；使用群聊时同时检查未 @ 不触发、不同发言人上下文隔离和提醒回原群。
- 邮箱真实连接成功，一封新增邮件被检测到并收到提醒，再检查一轮确认不重复。
- 视频真实转写和视觉端点完成一段有音轨的上传视频。
- Claude / Codex 如需要使用，分别提供有效认证并实际完成一次对话和工具调用。

不要把名称带 `[本地验收]` 的测试端点当作真实模型配置。最新执行证据与尚未验证的项目记录在 [验收报告](acceptance.md)。
